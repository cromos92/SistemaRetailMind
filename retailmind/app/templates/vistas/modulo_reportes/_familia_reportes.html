{% comment %} Tira de navegación entre reportes de una misma familia (ventas / existencias / logistica / compras). Uso, justo debajo del header del módulo: {% include 'vistas/modulo_reportes/_familia_reportes.html' with familia='ventas' activo='sucursal' %} - `familia`: ventas | existencias | logistica | compras - `activo`: clave del reporte actual dentro de la familia (se resalta) Inventario y familias: docs/FAMILIAS_REPORTES_2026-09.md. No toca datos ni el JS de cálculo de cada reporte: es navegación pura. Al hacer clic conserva del query string actual SOLO los filtros compartidos (fechas, año, mes, sucursal, marca) para que cambiar de reporte no pierda el contexto. Filtros compartidos (`window.FiltrosReporte`, definido abajo): cada reporte, al arrancar, pone en sus controles lo que traiga la URL (`FiltrosReporte.leer()`) y, al consultar, deja la URL con el estado actual (`FiltrosReporte.reflejar()`, history.replaceState). En la URL viajan SIEMPRE los nombres canónicos `fecha_inicio`, `fecha_fin`, `mes`, `anio`, `sucursal_id`, `marca_id`; los alias históricos (`fecha_desde`, `desde`, `sucursal`, `marca`…) se aceptan al leer. Las APIs de cada reporte no cambian: cada template traduce a sus nombres. Permisos: cada enlace se pinta solo si el usuario puede abrir ese reporte, con el mismo `puede_ver_opcion_tag` (y los mismos códigos de OpcionMenu que middleware_permisos.URL_PERMISO_MAP) que usa el menú; el reporte activo se pinta siempre. Sin esto, un cajero o jefe de local veía accesos que al hacer clic lo sacaban a bienvenida con "Acceso denegado". Estilos: mismos `quick-filter-btn` de ESTILOS_MODULOS.md (paleta #405189 → #0ab39c), acotados a `.familia-reportes` para no pisar los quick-filter propios de cada vista. {% endcomment %} {% load permisos_tags %}
